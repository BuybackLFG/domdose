# Адаптация legacy-датасета vl.ru/off (приближённый MVP-контур)

Файл `dataset/output/utility-rating.json` собран адаптером
`sources/legacy_dataset.py` из старой выгрузки
`dataset/legacy/events_parsed.json` (источник: объявления vl.ru/off) поверх
текущего draft (`dataset/pilot_dataset_draft.json`: houses, window, registry).

## Командa воспроизведения

Адаптер проверяет набор через запущенный internal scoring по
`DOMDOSSE_SCORING_URL` (по умолчанию `http://127.0.0.1:8001`). Сначала запустить
scoring в отдельном терминале из корня репозитория:

```powershell
.venv\Scripts\python.exe -m uvicorn api.scoring_main:app --port 8001
```

Затем:

```powershell
.venv\Scripts\python.exe -m sources.legacy_dataset `
  --legacy dataset\legacy\events_parsed.json `
  --current dataset\pilot_dataset_draft.json `
  --output dataset\output\utility-rating.json
```

Существующий output без `--force` не перезаписывается. Перед атомарной записью
(временный файл + replace) собранный датасет обязательно проходит операцию
`score_city` internal scoring (внутри — `parse_dataset` по опубликованной схеме и
расчёт); при отказе набора или недоступном scoring прежний output сохраняется даже
с `--force`.

## Что перенесено

* Справочник 20 домов, окно 30 дней и registry-поля — из текущего draft;
  события draft не используются.
* Только реальные записи старой выгрузки; никаких выдуманных или подогнанных
  под желаемые баллы значений.

## Допущения и эвристики MVP (важно: это не полное доказанное покрытие)

1. **Покрытие не доказано.** `coverage: complete` и `registry_complete: true`
   выставлены по решению владельца ради MVP-расчёта. Реально источник —
   объявления vl.ru/off: это публичные сообщения об отключениях, а не
   официальный полный журнал сетевых организаций. Дома без событий в файле
   могут как не иметь отключений, так и не попадать в выборку источника.
   Точность покрытия не гарантируется и не заявляется как 100%.
2. **Timezone.** Timestamp'ы старой выгрузки без смещения приняты как локальное
   владивостокское время и получили `+10:00` (явное допущение MVP).
3. **`kind`.** `planned` только если причина содержит прямое слово «планов»;
   всё остальное считается `emergency` — эвристическое допущение MVP, решение
   владельца. Реальная классификация аварийность/плановость по источнику не
   всегда однозначна.
4. **Отсутствующий `end`.** Записи без окончания пропускаются: неизвестное
   окончание не выдаётся за продолжающееся событие (из 1551 записи,
   пересекающих окно, 8 отброшены из-за отсутствующего `end`).
5. **`is_mass`.** `true` при `declared_n >= 2`, либо запись содержит 2+ адресов,
   либо инцидент после сопоставления затрагивает 2+ дома пилотной выборки.
6. **`is_natural_disaster`.** `true` только по прямым словам причины:
   стих/погод/ливен/ураган/шторм/снегопад/гололед/сильн.*ветер.
7. **Сопоставление адресов.** Точное, без fuzzy: нормализация (casefold, ё→е,
   Unicode-пробелы, удаление обозначений улица/ул/проспект/пр-кт/переулок/пер/
   бульвар/набережная/пл/шоссе/мкр и дом/д), для улицы сравнение множеств
   токенов (допускает «1-я Пригородная» == «Пригородная 1-я»), номер дома
   casefold-точно. Соседние дома не склеиваются. Одна старая запись может
   породить события для нескольких текущих домов. Адреса вида «19 кор 1»,
   «15/1» не сопоставляются с «19»/«15» — это сужает покрытие.
8. **Окно.** Событие входит при `start < window_end` и
   `(end IS NULL — уже отброшено) end > window_start`; фактические start/end
   сохраняются, клиппирование к окну выполняет scorer.
9. **Дедупликация.** Для одного (house_id, category, start, end) остаётся одна
   запись: `source_url` наименьшего `vl_id`, флаги OR, при конфликте `kind`
   побеждает `emergency`. Разные start/end и разные категории не склеиваются.

## Фактический результат прогона (2026-11-13)

* Событий: **66** (hot_water 23, cold_water 9, electricity 8, heating 26);
  все `kind` корректны, mass=66, disaster=2.
* Затронуто **10 из 20** домов выборки.
* Распределение overall: **good(≥0.8)=11, medium(0.4–0.8)=8, bad(<0.4)=1**;
  min=0.3322 (Шилкинская, 10), max=1.0, distinct=11.
* Output прошёл `parse_dataset` по опубликованной схеме и `score_city`.

## Ограничения

* Результат описывает только выбранные 20 домов и приближённую историю
  vl.ru/off за окно; его нельзя выдавать за среднее или рейтинг Владивостока.
* Дома без событий = «нет зафиксированных отключений в источнике», а не
  доказанная надёжность.
* Точность адресного сопоставления и эвристик `kind`/mass не проверялась
  вручную по каждой записи.
