# Предметная область «ДомДосье»

## Назначение MVP

Сервис оценивает надёжность покупки и аренды жилья во Владивостоке. Пользователь
вводит адрес или ссылку на объявление и получает досье конкретного дома: известную
историю и возможные проблемы.

Первый модуль досье — рейтинг надёжности коммунальных услуг по истории отключений
в сравнении с остальными домами города. Этот документ фиксирует только требования,
полученные от владельца в текущей итерации. Материалы прошлых итераций не являются
источником требований.

## Категории и окно расчёта

Категории:

* `hot_water` — горячая вода;
* `cold_water` — холодная вода;
* `electricity` — электричество;
* `heating` — отопление.

Расчёт ведётся по скользящему окну в 30 дней. Городской контур расчёта — все дома
Владивостока в справочнике, включая дома без отключений. Часовой пояс, точная граница
окна и правило для событий, частично попадающих в него, должны быть определены
контрактом модуля до реализации хранилища и API.

## Вес события

Базовый вес:

* аварийное отключение — `1,0`;
* плановое отключение — `0,4`.

Для массового события или события, вызванного стихией, применяется дополнительный
множитель `0,5`. В первой реализации множитель применяется один раз, если присутствует
хотя бы один из этих признаков; двойное понижение за сочетание обоих признаков не
используется. Это рабочее решение владелец может пересмотреть вместе с правилами
будущего набора данных.

## Метрики дома

Для каждого события `i` вычисляется итоговый вес:

```text
w_i = base_weight_i * (0,5, если событие массовое ИЛИ стихийное, иначе 1)
```

Для длительности события в часах `duration_i` по каждой категории рассчитываются три
метрики:

```text
frequency = Σ w_i
hours = Σ (w_i * duration_i)
longest = max(w_i * duration_i); для пустого списка longest = 0
```

Таким образом, сначала взвешивается длительность каждого события, затем берётся максимум.
Например, аварийное событие на 5 часов и плановое на 10 часов дают `frequency = 1,4`,
`hours = 9` и `longest = 5`, а не 4.

Нулевые метрики пустого списка событий означают отсутствие отключений только при доступных
исходных данных. Среднее по городу — сумма значений метрики по всем домам, делённая на
полное число домов; дома с нулём не исключаются из знаменателя. Оцениваемый дом входит
в полное число городских домов ровно один раз. Пустой городской справочник не даёт
корректного расчёта: это состояние «нет данных», а не нулевое среднее.

## Штраф за превышение среднего

Дом не получает штраф, пока его метрика не превышает среднюю по городу. После этого
штраф растёт по логарифмической шкале и ограничен единицей:

```text
ratio = house_metric / city_average
penalty = 0,                         если ratio <= 1
penalty = min(1, log2(ratio) / 3),   если ratio > 1
```

Опорные значения:

| Превышение среднего | Штраф |
|---|---:|
| до 2× включительно | от 0 до 1/3 |
| 4× | 2/3 |
| 8× и больше | 1 |

Если среднее конкретной метрики равно нулю, все значения именно этой метрики в корректном
неотрицательном городском контуре также равны нулю; её штраф равен нулю и деление не
выполняется. Остальные метрики рассчитываются независимо. Противоречивая пара
`house_metric > 0` и `city_average = 0` при полном городском контуре отклоняется как
некорректный вход.

## Рейтинг категории

Рейтинг начинается с `1,0` и снижается только за превышение городского среднего:

```text
category_score = 1 - (
    0,4 * frequency_penalty
    + 0,4 * hours_penalty
    + 0,2 * longest_penalty
)
```

Диапазон рейтинга категории — от `0,0` до `1,0`.

## Общий рейтинг коммунальных услуг

Веса категорий:

| Категория | Вес |
|---|---:|
| Электричество | 0,30 |
| Холодная вода | 0,25 |
| Отопление | 0,25 |
| Горячая вода | 0,20 |

Сначала вычисляется взвешенная сумма категорий, затем применяется ограничение:

```text
overall_score = min(weighted_score, worst_category_score + 0,25)
```

Для численного общего рейтинга необходимы исходные данные всех четырёх категорий по полному
городскому контуру. Отсутствие данных хотя бы одной категории означает «нет данных» для
общего рейтинга; веса оставшихся категорий не перенормируются, а недоступная категория не
получает оценку `1,0`.

## Данные и честность результата

Сбор и подготовка набора данных выполняются отдельным согласованным этапом. До него
нельзя выдавать демонстрационные или случайные значения за реальную историю дома.
Тестовые события допустимы только в явно обозначенных тестах и локальных fixtures.
Ответ API и интерфейс должны различать отсутствие отключений и отсутствие данных.
