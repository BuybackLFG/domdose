# Предметная область «ДомДосье»

## Назначение MVP

Сервис оценивает надёжность покупки и аренды жилья во Владивостоке. Пользователь
вводит адрес или ссылку на объявление и получает досье конкретного дома: известную
историю и возможные проблемы.

Первый модуль досье — рейтинг надёжности коммунальных услуг по истории отключений
в сравнении с пилотной выборкой из 20 домов. Этот документ фиксирует только требования,
полученные от владельца в текущей итерации. Материалы прошлых итераций не являются
источником требований.

## Категории и окно расчёта

Категории:

* `hot_water` — горячая вода;
* `cold_water` — холодная вода;
* `electricity` — электричество;
* `heating` — отопление.

Расчёт ведётся по скользящему окну в 30 дней. Контур расчёта — ровно 20 домов:
по 4 в Ленинском, Первомайском, Первореченском, Советском и Фрунзенском районах,
включая дома без отключений. Это пилотная выборка, а не городская генеральная совокупность;
результат нельзя выдавать за средний или рейтинг всего Владивостока. Все моменты времени
имеют смещение `+10:00`. Окно полуоткрытое `[window_start, window_end)`: событие входит при
`started_at < window_end` и `(ended_at IS NULL ИЛИ ended_at > window_start)`. Длительность
клиппируется к границам окна; для продолжающегося события окончанием служит `window_end`.
Мгновенное событие нулевой длительности допускается только строго внутри окна.

## Вес события

Базовый вес:

* аварийное отключение — `1,0`;
* плановое отключение — `0,4`.

Для массового события или события, вызванного стихией, применяется дополнительный
множитель `0,5`. В первой реализации множитель применяется один раз, если присутствует
хотя бы один из этих признаков; двойное понижение за сочетание обоих признаков не
используется. Это рабочее решение владелец может пересмотреть вместе с правилами
будущего набора данных.

## Метрики дома

Для каждого события `i` вычисляется итоговый вес:

```text
w_i = base_weight_i * (0,5, если событие массовое ИЛИ стихийное, иначе 1)
```

Для длительности события в часах `duration_i` по каждой категории рассчитываются три
метрики:

```text
frequency = Σ w_i
hours = Σ (w_i * duration_i)
longest = max(w_i * duration_i); для пустого списка longest = 0
```

Таким образом, сначала взвешивается длительность каждого события, затем берётся максимум.
Например, аварийное событие на 5 часов и плановое на 10 часов дают `frequency = 1,4`,
`hours = 9` и `longest = 5`, а не 4.

Разные инциденты одной категории одного дома считаются независимо, даже если пересекаются по
времени: их взвешенные длительности суммируются в `hours`, а не объединяются по перекрытию.
Дублем считается только полностью совпадающая запись инцидента.

Нулевые метрики пустого списка событий означают отсутствие отключений только при доступных
исходных данных. Среднее по выборке — сумма значений метрики по 20 домам, делённая на 20;
дома с нулём не исключаются из знаменателя. Оцениваемый дом входит в выборку ровно один раз.
Пустой или неполный набор из 20 домов не даёт корректного расчёта: это состояние «нет данных»,
а не нулевое среднее.

## Штраф за превышение среднего

Дом не получает штраф, пока его метрика не превышает среднюю по выборке. После этого
штраф растёт по логарифмической шкале и ограничен единицей:

```text
ratio = house_metric / sample_average
penalty = 0,                         если ratio <= 1
penalty = min(1, log2(ratio) / 3),   если ratio > 1
```

Опорные значения:

| Превышение среднего | Штраф |
|---|---:|
| до 2× включительно | от 0 до 1/3 |
| 4× | 2/3 |
| 8× и больше | 1 |

Если среднее конкретной метрики равно нулю, все значения именно этой метрики в корректной
неотрицательной выборке также равны нулю; её штраф равен нулю и деление не выполняется.
Остальные метрики рассчитываются независимо. Противоречивая пара `house_metric > 0` и
`sample_average = 0` при полном наборе из 20 домов отклоняется как некорректный вход.

## Рейтинг категории

Рейтинг начинается с `1,0` и снижается только за превышение среднего по выборке:

```text
category_score = 1 - (
    0,4 * frequency_penalty
    + 0,4 * hours_penalty
    + 0,2 * longest_penalty
)
```

Диапазон рейтинга категории — от `0,0` до `1,0`.

## Общий рейтинг коммунальных услуг

Веса категорий:

| Категория | Вес |
|---|---:|
| Электричество | 0,30 |
| Холодная вода | 0,25 |
| Отопление | 0,25 |
| Горячая вода | 0,20 |

Сначала вычисляется взвешенная сумма категорий, затем применяется ограничение:

```text
overall_score = min(weighted_score, worst_category_score + 0,25)
```

Худшая категория дома (`weakest`) — категория с минимальной оценкой; именно её оценка
`worst_category_score` участвует в ограничении. При равенстве минимальных оценок выбирается
первая в каноническом порядке: горячая вода, холодная вода, электричество, отопление.
Худшая категория не является отдельной независимой оценкой. Если оценки всех четырёх
категорий равны `1,0`, худшая категория в интерфейсе не показывается.

Для численного общего рейтинга необходимы исходные данные всех четырёх категорий по полному
набору из 20 домов. Отсутствие данных хотя бы одной категории означает «нет данных» для
общего рейтинга; веса оставшихся категорий не перенормируются, а недоступная категория не
получает оценку `1,0`.

## Данные и честность результата

Сбор и подготовка набора данных выполняются отдельным согласованным этапом. До него
нельзя выдавать демонстрационные или случайные значения за реальную историю дома.
Тестовые события допустимы только в явно обозначенных тестах и локальных fixtures.
Ответ API и интерфейс должны различать отсутствие отключений и отсутствие данных.
