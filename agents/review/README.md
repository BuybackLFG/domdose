# Промпты враждебного ревью по модулям

Самостоятельные задания для логической роли `u-reviewer` (определение — `agents/reviewer.md`).
Каждый файл — готовый prompt одного модуля: правила работы, объект, чек-лист атак и граничных
случаев, метод проверки и формат отчёта. Промпты не ссылаются друг на друга и выдаются ребёнку
целиком (раздел 21 AGENTS.md: самостоятельный текст без «см. выше»).

| Файл | Модуль |
|---|---|
| `scoring.md` | критичный контур скоринга: `utility_rating`, `contract`, `docs/DOMAIN.md` |
| `backend.md` | публичный API, внутренний scoring, клиент и протокол, `dossier`, `core` |
| `frontend.md` | SPA: React, Leaflet-карта, поиск, состояния, клиент API |
| `infra.md` | Nginx, Compose, Dockerfile, зависимости сборки, публикация на VPS |
| `pipeline-map.md` | конвейер данных (legacy-адаптер, загрузка JSON, `dataset/`) и подготовка карты |
| `joints.md` | стыки слоёв: сквозные контракты, коды ошибок, readiness, данные и карта |
| `tests-docs.md` | качество всей мерки, документация, мёртвый код и дубли |

## Параметры

Перед выдачей замените плейсхолдеры фактическими значениями:

| Плейсхолдер | Смысл |
|---|---|
| `<WORKTREE>` | рабочая копия ревьюируемой ветки |
| `<REF>` | коммит или ветка, которые ревьюируются |
| `<SCRATCH>` | каталог временных файлов вне репозитория; ребёнок пишет только в `<SCRATCH>/<модуль>/` |
| `<PYTHON>` | интерпретатор окружения проекта с `requirements-dev.txt` |
| `<MAP_PYTHON>` | интерпретатор окружения `requirements-map.txt` (только для `pipeline-map.md`) |
| `<PROTECTED>` | стенды владельца, которые нельзя трогать (Docker-проекты, порты) |

## Как запускать

* Модель — думающая роль: по решению владельца ревьюеры работают на `opus`.
* Модули независимы и запускаются параллельно; ревьюеры только читают, поэтому зоны записи не
  пересекаются (каждый пишет лишь в свой подкаталог `<SCRATCH>`).
* Находки не исправляются ревьюером. Главный агент сводит их в план: сначала мерка
  (`u-tester`), затем реализация (`u-executor`/`u-frontend`), отдельными коммитами.
* После каждого проверенного модуля обновляется `TODO.md` ветки.
