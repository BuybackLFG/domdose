# Ревью модуля: frontend — SPA, карта, поиск, клиент API

Логическая роль: `u-reviewer` — независимое враждебное ревью. Модель: `opus`.

## Правила работы
* Только чтение: не меняй файлы репозитория, не коммить, не запускай подагентов. Если нужна
  другая роль — верни заказ по форме раздела 21 AGENTS.md финальным текстом.
* Временные копии, скрипты, мутанты и логи — только в `<SCRATCH>/frontend/`. Собственный
  `vite` поднимай из копии на свободном порту; стенды `<PROTECTED>` только читать (GET), не менять.
* Никаких обращений во внешние сервисы с кодом, данными или именем проекта (без `npm audit` и
  запросов к реестрам). Об уязвимостях версий — из своей памяти с пометкой уверенности.
* Мерило — AGENTS.md (разделы 6, 8, 12, 13).

## Контекст
SPA показывает карту 20 домов (Leaflet, один локальный `L.imageOverlay` с двумя уровнями
детализации), список, поиск по каталогу, сводку, события и оценки категорий. Данные приходят из
`/api` того же origin; Nginx отдаёт документ SPA только при готовом наборе. Сервис публикуется в
интернет. Сегодня данные — файл оператора, позже появится ввод из объявлений: считай любые
строки из API недоверенными. Рабочая копия `<WORKTREE>`, ревьюируется `<REF>`. Frontend:
`frontend/` (`npx vitest run`, `npx tsc -b`, `npm run lint`, `npm run build`).

## Объект
`frontend/src/**` (features/dossier, lib, test), `frontend/index.html`, `frontend/vite.config.ts`,
`frontend/package.json`, `frontend/package-lock.json`, `frontend/public/maps/*.manifest.json`.

## Чек-лист
### A. XSS и инъекции
* Каждое место, где строка из API попадает в DOM в обход экранирования React: Leaflet
  `bindTooltip`/`bindPopup`/`divIcon({html})`/`title`/`alt` (вставляет ли Leaflet строку как
  `innerHTML`?), атрибуты, `dangerouslySetInnerHTML`, `innerHTML`.
* Ссылки `source_url`: схемы `javascript:`, `data:`, `vbscript:`, относительные и
  protocol-relative URL; `rel="noopener noreferrer"`, `target`; валидирует ли клиент схему.
* Поиск: ввод в `RegExp` без экранирования (ReDoS, инъекция), очень длинный ввод, спецсимволы,
  Unicode-нормализация и регистр.
* Подмена ответа API: `house_id`, адрес, категория с HTML/скриптом — что отрисуется.

### B. CSP same-origin
Нет inline-скриптов, `eval`, `new Function`, внешних шрифтов/картинок/стилей; совместимость с
`default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:`; можно ли
убрать `'unsafe-inline'` для стилей (Leaflet ставит inline-стили — оцени цену).

### C. Устойчивость к враждебному или битому ответу API
Неожиданные типы, лишние поля, пустые и огромные списки, NaN/отрицательные/>1 оценки,
неизвестные категории и `kind`, отсутствие `weakest`, дубли `house_id`, больше 20 домов, кривые
даты. Что валидирует `features/dossier/api.ts` и `lib/api.ts`, как сообщается отказ, есть ли
error boundary (белый экран при исключении в рендере?).

### D. Состояния и гонки
Отмена устаревших запросов (`AbortController`) при быстром выборе домов; повтор после ошибки;
разделение loading / empty / error / «нет событий» / «нет исходных данных»; 503 с
`X-DomDossier-Error` на `/api/*` во время работы SPA; отказ загрузки подложки; потеря сети.

### E. Карта
Преобразование координат (lat/lon не перепутаны, внутри bounds), `maxBounds`, `minZoom` покрытия
при resize, `ResizeObserver` и утечки обработчиков при размонтировании, переключение уровня
подложки без второго слоя, клавиатурная доступность маркеров, предупреждение о домах без маркера.

### F. Доступность (a11y)
Фокус и его потеря (пагинация, фильтр, поиск), роли и имена, `aria-pressed`/`aria-busy`,
контраст, работа только с клавиатуры, `prefers-reduced-motion`.

### G. Зависимости и сборка
Версии из `package-lock.json` (известные проблемы — по памяти), неиспользуемые зависимости,
размер бандла (manifest целиком в JS), source maps в production, `vite.config.ts` (proxy только
для dev, `host: true` — риск в dev).

### H. Мутанты на копии
Санитаризация и валидация ссылок, отмена запросов, валидация ответа, скрытие `weakest`, фильтр и
пагинация, координаты маркеров — выжившие мутанты являются находками.

## Формат отчёта
1. Сводка: 3–5 строк.
2. Находки по убыванию серьёзности: **БЛОКЕР** (эксплуатируемый XSS/обход, белый экран),
   **ВАЖНО** (реальный риск, выживший мутант), **ЗАМЕЧАНИЕ**. Для каждой: файл и символ
   (file:line допустимы в отчёте), сценарий атаки или вход → ущерб, нарушенное правило,
   механизм исправления, какой прибор должен краснеть, уверенность — «подтверждено» или
   «предположение».
3. Проверено и корректно — кратко.
4. Команды и фактический вывод, пути к логам в `<SCRATCH>/frontend/`.
5. Не проверялось и почему.
