# Ревью модуля: инфраструктура — Nginx, Compose, образы, публикация на VPS

Логическая роль: `u-reviewer` — независимое враждебное ревью. Модель: `opus`.

## Правила работы
* Только чтение: не меняй файлы репозитория, не коммить, не запускай подагентов. Если нужна
  другая роль — верни заказ по форме раздела 21 AGENTS.md финальным текстом.
* Временные файлы, override-файлы Compose и логи — только в `<SCRATCH>/infra/`. Для эмпирики
  собирай образы и поднимай отдельный временный проект (`docker compose -p <уникальное имя>`)
  на другом опубликованном порту через override в `<SCRATCH>`; после — `down` и удаление только
  своих объектов. `<PROTECTED>` не трогать.
* Нагрузку держи в разумных пределах машины разработчика; это проба поведения, а не DDoS.
* Никаких обращений во внешние сервисы с кодом, данными или именем проекта.
* Мерило — AGENTS.md (разделы 6, 14, 15, 17, 25) и README.md.

## Контекст
Стек: `frontend` (Nginx, SPA, ворота данных `auth_request` → `api /api/ready`, прокси `/api/`),
`api` (FastAPI), `scoring` (внутренний HTTP). Сети `internal` (`internal: true`) и `edge` (только
frontend, для публикации порта). Публикация на VPS владельца: открыты 22, 80, 443 и 8000; домена
пока нет. Решение владельца: сейчас HTTP на 80, при появлении домена — автоматически HTTPS
(Let's Encrypt, 443, редирект, HSTS); `api` и `scoring` наружу не публикуются, порт 8000 не
используется. Сервис будут атаковать. Рабочая копия `<WORKTREE>`, ревьюируется `<REF>`.

## Чек-лист
### A. Nginx как единственная точка входа
* Rate limiting: `limit_req`/`limit_conn` по IP для документов, `/api/`, `/maps/`; отдельный
  лимит для дорогих путей; ответ 429; поведение за прокси (`real_ip`, доверие к
  `X-Forwarded-For` только от известного источника).
* Лимиты: `client_max_body_size` (у сервиса нет загрузок), `large_client_header_buffers`,
  `client_header_timeout`, `client_body_timeout`, `send_timeout`, `keepalive_timeout`,
  `keepalive_requests`, `proxy_read_timeout`; медленные клиенты (slowloris).
* Разрешённые методы (только GET/HEAD, остальным 405/444), `default_server` и мусорный `Host`,
  `server_tokens off`, `absolute_redirect`, обработка `..`, `%2e`, `//`, длинных URI.
* Ворота данных: усиление нагрузки (подзапрос к api на каждый документ; при битом наборе api
  перечитывает файл и вызывает scoring на каждый запрос) — нужно ли кэшировать результат ворот
  на секунды; может ли клиент достучаться до `/_gate` и `@`-location снаружи; кэшируется ли 503.
* Заголовки: CSP, `X-Content-Type-Options`, `Referrer-Policy`, COOP/CORP, `Permissions-Policy`,
  `frame-ancestors`, HSTS только при TLS; присутствие на 4xx/5xx; `Cache-Control` для документов,
  `/assets/`, `/maps/`.
* Что раскрывают наружу `/health`, `/ready`, `/api/ready`, `X-DomDossier-Error`, страницы
  ошибок; нужно ли закрыть readiness-маршруты от внешнего мира.
* Журнал: рост без ротации → заполнение диска; что пишется на каждый запрос; query и IP.

### B. Контейнеры
* Пользователь (frontend Nginx от root?), `read_only`, `tmpfs`, `cap_drop: [ALL]` с минимальным
  `cap_add`, `security_opt: no-new-privileges`, лимиты `mem_limit`/`cpus`/`pids_limit`, `ulimits`,
  `restart`-политика, `init`, сигналы остановки, частота healthcheck и шум в журналах.
* Ротация журналов: файл в named volume (logrotate внутри? размер?), драйвер логов Docker
  (`max-size`, `max-file`).
* Образы: пины тег+digest, процедура обновления, лишние утилиты, размер; supply chain — `npm ci`
  по lockfile, `pip -c constraints.txt` (без хэшей — оцени `--require-hashes`).

### C. Сеть и исходящий трафик
`internal`/`edge`, исходящий доступ frontend через `edge` и как его закрыть; публикация
`127.0.0.1:8080` против нужной для VPS; что слушает на хосте после `up`; IPv6.

### D. Публикация на VPS (решение владельца выше)
Предложи конкретную конфигурацию: edge-прокси (Caddy или Nginx+ACME) — единственный сервис с
`ports: 80, 443`; переключение HTTP→HTTPS по переменной домена в `.env`; хранение сертификатов в
volume; редирект 80→443 и HSTS только при домене; `frontend` уходит во внутреннюю сеть;
исключение из правила «runtime без интернета» только для ACME; брандмауэр хоста (22/80/443,
закрыть 8000, если не нужен); риски и цена каждого решения. Отдельно — что сделать, пока домена
нет (HTTP на 80 с теми же лимитами и заголовками, без HSTS).

### E. Эмпирика на временном проекте
Измерь и зафиксируй статусы и строки журналов: 200–1000 параллельных запросов к `/` и
`/api/houses`; медленный клиент; заголовок 64 КБ; методы `POST/PUT/DELETE/TRACE/PROPFIND`;
запросы к `/_gate`, `@data_unavailable`, `/../etc/passwd`, `/%2e%2e/`, `//api//houses`; мусорный
`Host`; URI 8 КБ; запрос при остановленном `api` и при битом наборе.

### F. Мерка
Какие статические сторожа в `tests/test_compose.py` закрепляют найденные механизмы и какие
нужно добавить; какие свойства проверяются только эмпирически (поставь их в план приёмки).
