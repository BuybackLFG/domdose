# ДомДосье

Краткий MVP сервиса оценки надёжности покупки и аренды жилья во Владивостоке.
Пользователь вводит адрес или ссылку на объявление и получает досье конкретного дома.

Первый модуль — рейтинг надёжности коммунальных услуг по отключениям горячей и
холодной воды, электричества и отопления за скользящие 30 дней. Формула и веса —
в `docs/DOMAIN.md`.

## Текущее состояние

Созданы исходная основа проекта, чистое математическое ядро скоринга и строгий
JSON-загрузчик пилотной выборки с независимыми проверками. FastAPI, frontend и набор
реальных данных ещё не реализованы. Документы прошлых итераций не являются источником
требований.

Самостоятельный комплект для внешней модели находится в `dataset/`: промпт, strict-схема
и инструкция сохранения. Расчётный контур MVP — пилотная выборка из 20 домов, по 4 в каждом
из пяти районов; среднее и рейтинг относятся только к этой выборке, а не ко всему городу.
Итоговый реальный датасет записывается в `dataset/output/utility-rating.json` и не коммитится.
До его появления приложение не должно выдавать тестовые значения за реальное досье дома.

## Архитектурный стиль

За образец принят `C:\Progg\Thunderbird\tariff_parser_fin`, но его предметная логика
не переносится. Перенимаются только:

* небольшие пакеты по технической ответственности с явными дверями, а не одинаковые
  слои в каждом пакете;
* направленные зависимости без обратных ссылок;
* централизованные конфигурация и логирование;
* неизменяемые dataclass/Enum внутри и Pydantic на HTTP/конфигурационной границе;
* изоляция внешних источников адаптерами;
* изоляция базы репозиториями;
* абсолютные импорты;
* тесты-сторожа архитектурных границ и расчётных инвариантов.

Для MVP сохраняется KISS: новые слои и пакеты появляются вместе с реальным сценарием,
а не заранее пустыми каталогами.

## Ветки

* `main` — общая основа, регламент и принятые изменения;
* `module/<имя>` — отдельная ветка каждого прикладного модуля;
* первый модуль разрабатывается в `module/utility-rating`;
* изменения одного модуля не смешиваются с реализацией другого;
* коммиты выполняются только в локальном репозитории, удалённый репозиторий не задан.

## Регламент и агенты

* `AGENTS.md` — обязательные правила проекта, команды и границы;
* `main-persona.md` — роль главного оркестратора и выбор моделей;
* `agents/` — определения специализированных ролей;
* `docs/DOMAIN.md` — предметные правила рейтинга;
* `dataset/README.md` — запуск сбора и путь итогового датасета.

## Локальная среда

Проверено в среде создания проекта: Python 3.13, Node.js 24, npm 11 и Docker доступны.
Команды установки, запуска и проверки будут добавлены вместе с соответствующими
приложениями; до этого они не считаются работающими командами проекта.
